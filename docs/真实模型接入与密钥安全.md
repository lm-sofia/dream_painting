# 真实模型接入与密钥安全（第 7 课教学文档）

> 面向"别人拿到你的代码也能用"的工程实践：**代码公开，密钥私有**。

---

## 一、密钥安全三原则（背下来）

| 原则 | 做法 | 为什么 |
|---|---|---|
| **密钥永不进 Git** | 真密钥只写在 `backend-java/.env`（已被 `.gitignore` 排除） | 仓库 = 公开副本，一旦 push 历史里有过密钥，删掉也没用（Git 历史可翻） |
| **仓库只放占位模板** | 提交 `.env.example`（值全是占位符） | 别人 clone 后复制成 `.env` 填自己的 Key，代码零改动 |
| **前端零密钥** | Key 只在后端环境变量，前端只传描述/风格 | 浏览器里任何代码任何人可见，密钥放前端 = 裸奔 |

**密钥泄露的后果**：任何人拿到你的 API Key 都能调用模型 → 直接烧你的钱（这就是为什么火山方舟控制台建议给 Key 设**限额**）。

## 二、本项目怎么做的（分层）

```text
别人 clone 仓库
   │
   ├─ 仓库里有：.env.example（占位） + application.yml（${ARK_API_KEY:} 占位引用）
   │
   └─ 别人自己：
       ① 复制 .env.example → .env
       ② 去火山方舟控制台买 Key，填入 .env
       ③ 运行 start-prod.ps1  →  脚本读 .env → 注入环境变量 → 启动后端
       ④ 后端启动时 @Value("${ai.video.seedance.api-key}") 读到 Key
```

关键代码（`SeedanceVideoGenerator`）：

```java
@Value("${ai.video.seedance.api-key}") String apiKey   // 从环境变量注入，绝不写死
...
.header("Authorization", "Bearer " + apiKey)            // 调用时带上
```

启动即校验（fail fast）：`provider=seedance` 但 Key 为空 → **直接启动失败并提示**，防止"以为接了真模型结果白跑"。

## 三、可插拔引擎架构（换模型不用改业务代码）

```text
                    ┌─────────────────────────┐
业务代码(TaskService)│  VideoGenerator 接口      │
 只依赖接口          │  ├─ MockVideoGenerator    │ ← provider=mock（默认，无 Key 演示）
                    │  └─ SeedanceVideoGenerator│ ← provider=seedance（真实）
                    └─────────────────────────┘
```

- 换厂商（可灵/即梦/Runway…）= 新增一个实现类 + 改 `AI_VIDEO_PROVIDER` 配置
- worker（RealTaskWorker）和前端**一行都不用改**——这就是"面向接口编程"的红利

## 四、真实模型调用流程（火山方舟 Seedance 异步模型）

```text
1. submit  POST /api/v3/content/generation/tasks
   body: model + prompt(风格模板填充创意) + resolution + duration + seed(随机种子)
   → 返回 providerTaskId（落库 generation_tasks.provider_task_id）

2. query   GET /api/v3/content/generation/tasks/{id}   （每 2 秒轮询，幂等）
   → status: queued / running / succeeded / failed
   → succeeded 时返回 content.video_url

3. 完成   worker 按任务状态分支推进：AGENTS→RENDERING(85%)→COMPILING(92%)→SUCCESS(100%)
   → 视频 URL 落库 + 作品入库 + SSE 推给前端
```

**为什么用异步任务模型而不是直接返回**：视频生成动辄几十秒~几分钟，HTTP 同步等不了；所以"提交+轮询"是行业标准形态（所有主流视频 API 都这样）。

## 五、本次实战踩的 3 个坑（都真实发生过）

| 坑 | 现象 | 根因 | 修复 |
|---|---|---|---|
| 游离实体 | 任务 FAILED"引擎任务丢失" | worker 里 `task.setProviderTaskId()` 只改内存（实体不在事务内），advanceAgent 内部重新加载保存的是旧数据 | 新增 TaskService.saveProviderTaskId()（事务内加载+保存） |
| 查询非幂等 | 走到 RENDERING 后 FAILED"任务不存在" | Mock 第一次查 SUCCEEDED 就删记录，后续轮询查不到 | 查询不删记录 + 5 分钟超时清理 |
| 缓存版本不兼容 | GET /styles 500 | Docker 旧容器用旧序列化器写入 Redis，新代码（带类型信息）读旧格式炸 | 清 Redis 缓存；**生产规范：发布时清缓存或缓存 key 带版本号** |

## 六、你自己开真实模型（3 分钟）

1. 注册火山引擎（volcengine.com）→ 开通方舟 → 创建 API Key（**建议设置限额**）
2. 本机执行：
```powershell
cd D:\AI-project\backend-java
Copy-Item .env.example .env
# 编辑 .env：AI_VIDEO_PROVIDER=seedance + 填入 ARK_API_KEY
./start-prod.ps1
```
3. 前端创作 → 提交后看任务进度 → 完成后作品库就是**真实生成**的视频（不同描述/风格/seed 结果不同）

> ⚠️ 注意：真实生成按次计费。契约测试/E2E 请在 mock 模式下跑（默认），避免误烧额度。
