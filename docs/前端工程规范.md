## 1. 接口参数规范（前后端契约基线）

### 1.1 统一响应结构（所有 HTTP 接口）

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "traceId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| code | int | 0 = 成功；非 0 = 业务错误（见错误码表） |
| message | string | 人类可读信息（前端可 toast 展示） |
| data | any | 业务数据；无返回体时可为 null |
| traceId | string | 全链路追踪 ID（网关生成，排障关键） |

### 1.2 统一错误码

| 错误码 | HTTP 状态 | 含义 | 前端行为 |
|---|---|---|---|
| 0 | 200 | 成功 | 正常处理 |
| 40001 | 400 | 参数非法 | 表单校验提示，不弹 toast |
| 40101 | 401 | 未登录/token 过期 | 清除本地 token → 跳登录页（保留当前路由） |
| 40301 | 403 | 内容违规被拦截 | 提示"内容不符合规范，请修改后重试"（不泄露具体词） |
| 40302 | 403 | 无权限（非本人资源） | 返回上一页 |
| 40401 | 404 | 资源不存在 | 显示空态 |
| 40901 | 409 | 状态冲突（如渲染中取消） | 展示后端 message |
| 42901 | 429 | 额度不足/触发限流 | 弹升级会员引导（心流断点） |
| 50001 | 500 | 生成失败 | 失败页 + 重试按钮 |
| 50301 | 503 | 模型不可用/服务降级 | 降级提示 + 稍后重试 |

### 1.3 分页规范（列表类接口统一）

```json
// 请求：GET /api/v1/posts?cursor=xxx&limit=20&sort=hot
// 响应 data:
{
  "items": [],
  "nextCursor": "base64token",   // null = 没有更多
  "hasMore": true
}
```

- **游标分页**（不用 offset）：广场/评论等高频列表，避免深分页性能问题
- `limit` 上限 50，服务端强制 clamp
- 前端封装 `useCursorList` hook 统一处理

### 1.4 鉴权规范

- 请求头：`Authorization: Bearer <JWT>`；JWT 存 **localStorage**（非 HttpOnly cookie，因前后端分离）
- 刷新策略：access token 30min + refresh token 7d；axios 拦截器 401 时**单飞刷新**（并发请求只刷一次，其余排队）
- 游客：匿名 token（服务端签发，限流更严），注册后调用 `/auth/merge` 合并游客数据
- 所有写操作必须带 `Idempotency-Key`（客户端 uuid）请求头，服务端幂等

### 1.5 请求规范（axios 封装）

```typescript
// src/api/client.ts 核心约定（现有文件按此扩展）
- baseURL: '/api/v1'（开发走 Vite proxy，生产走 Nginx 反代，杜绝 CORS）
- 请求拦截：注入 token / Idempotency-Key（写请求）/ 请求重试标识
- 响应拦截：code!==0 统一处理（401 跳转、429 弹会员、其余 toast）
- 超时：普通接口 15s；文件上传 120s；导出轮询单独处理
- 取消：AbortController 支持，路由切换自动 abort 未完成请求
```

### 1.6 文件上传规范

- 直传对象存储：前端拿预签名 URL（`POST /api/v1/uploads/presign`）→ 直传 OSS/MinIO → 回调通知服务端
- 类型白名单：jpg/png/webp ≤10MB；mp4 ≤2GB（断点续传分片）
- 上传进度条必须（axios onUploadProgress）

### 1.7 实时进度（SSE）规范

- `EventSource /api/v1/creations/{id}/tasks/{taskId}/events`
- 事件类型：`task_status` / `step_update` / `done` / `error`
- **降级**：onerror 时切换 3s 轮询，恢复后切回 SSE
- 前端封装 `useTaskProgress(taskId)` hook，统一消费

## 2. 打包配置（Vite 优化基线）

### 2.1 已落地（vite.config.ts）

- **代码分包**（Rolldown groups）：react 全家桶 / antd / vendor(axios+zustand) / 业务代码 —— 命中浏览器缓存
- `chunkSizeWarningLimit: 600`

### 2.2 生产构建追加项（开发实施时应用）

```typescript
// vite.config.ts 追加（示意）
build: {
  minify: 'esbuild',            // 体积/速度平衡；体积优先可换 'oxc'
  cssMinify: 'lightningcss',    // 已有 lightningcss 依赖
  sourcemap: false,             // 生产关闭；错误监控用 sentry 上传 sourcemap
  target: 'es2020',             // 兼容基线：Chrome 80+/Safari 14+
  rollupOptions: { output: { manualChunks: { /* 按页面拆 canvas/video 重库 */ } } },
}
```

### 2.3 体积预算

| 指标 | 目标 |
|---|---|
| 首屏 JS（gzip） | ≤ 220KB（antd 按需 + react 分离后） |
| LCP | ≤ 2.5s（移动端 4G） |
| 单页面级 chunk | ≤ 200KB |

### 2.4 交付链路

- `npm run build` → `dist/`（静态文件 + 内容 hash）
- Nginx 托管：`gzip on` + `brotli`；静态资源 `Cache-Control: max-age=31536000, immutable`；`index.html no-cache`
- Docker 多阶段构建（现有 Dockerfile 已具备）

## 3. 性能优化规范

| 场景 | 方案 | 优先级 |
|---|---|---|
| 路由懒加载 | `React.lazy` + `Suspense`，按页面拆包 | P0 |
| 骨架屏 | 列表/详情/向导首次加载显示骨架，替代 loading 菊花 | P0 |
| 图片优化 | 封面/缩略图走 CDN + WebP + 尺寸裁剪（?w=400）；`loading="lazy"` | P0 |
| 广场瀑布流 | **虚拟滚动**（react-window / 自研 IntersectionObserver 池），只渲染可视区 | P0 |
| 播放器 | 首帧预加载 + 渐进式播放；离屏不加载（`preload="metadata"`） | P0 |
| 状态缓存 | Zustand + 路由级缓存；列表返回不重新拉取（60s 内） | P1 |
| 长任务 | 画布框选/时间线计算放 Web Worker，主线程不阻塞 | P1 |
| 防抖节流 | 搜索 300ms 防抖；点赞/关注幂等乐观更新 + 失败回滚 | P0 |
| 资源预取 | 用户悬停模板卡时 `prefetch` 其预览视频 | P1 |
| 包体积 | antd 按需引入（tree-shaking 已默认）+ 移除 moment 换 dayjs（已有） | P0 |

**性能预算验收**：Lighthouse Performance ≥ 90（移动端模拟）；bundle 分析用 `rolldown-vite --report`。

## 4. 安全规范

| 风险 | 防护 | 验收 |
|---|---|---|
| XSS | React 默认转义；`dangerouslySetInnerHTML` 全面禁用（审核文案等必须走净化库 DOMPurify）；用户昵称/标题渲染前转义 | 注入用例全过 |
| CSP | 生产 Nginx 配 `Content-Security-Policy`：`default-src 'self'; img-src 'self' https: data:; media-src 'self' https:; script-src 'self'`（必要时放宽到白名单 CDN） | 无 unsafe-inline |
| token 泄露 | 不存 localStorage 之外；不打印；日志脱敏；`X-Content-Type-Options: nosniff` | 代码扫描无硬编码 |
| 敏感信息 | 前端不存/不显 AK/SK、数据库密码、JWT_SECRET；环境变量经 Vite `import.meta.env.VITE_*` 白名单 | grep 审计 |
| 开放重定向 | 登录跳转 `redirect=` 参数白名单校验（仅站内路径） | 用例通过 |
| 依赖漏洞 | `npm audit` 进 CI；依赖锁定 lockfile；升级策略：次要/补丁自动，主版本人工 | CI 必过 |
| 点击劫持 | Nginx `X-Frame-Options: DENY`（分享页如需嵌入则 SAMEORIGIN） | 响应头检查 |
| 上传安全 | 前端校验类型/大小；真实校验在后端（MIME sniff + 魔数）；渲染走对象存储隔离域名 | 上传测试全过 |
| 越权 | 前端隐藏 ≠ 安全：所有资源操作必须携带 ownerId 校验（后端为准）；前端仅做 UX 层 | 契约测试覆盖 |

## 5. 组件封装规范

### 5.1 目录结构（扩展现有 src/）

```text
src/
├── api/            # 接口层：client.ts + 按域拆分（creation/template/post/me）
│   └── types/      # 与后端契约一致的 TS 类型（唯一来源：后端 OpenAPI 生成或手写同步）
├── components/     # 通用组件
│   ├── common/     # Button/Card/Empty 等业务通用件（基于 antd 二次封装）
│   ├── business/   # 业务组件：TemplateCard / PostCard / AgentProgress / VersionList
│   └── canvas/     # 画布域组件（CanvasStage / Timeline / InstructPanel）
├── hooks/          # useTaskProgress / useCursorList / useDebounce / useAuth
├── stores/         # Zustand：authStore / draftStore / canvasStore
├── pages/          # 路由页面（按路由 1:1）
├── router/         # 路由 + 守卫（登录态/会员态/游客态）
└── utils/          # 纯函数工具（格式化/脱敏/防抖）
```

### 5.2 组件设计五原则

1. **单一职责**：一个组件一件事；超过 150 行拆分子组件
2. **受控优先**：表单/状态组件默认受控，支持 value/onChange
3. **类型安全**：所有 props 用 TS 严格类型；禁止 `any` 外溢
4. **复用边界**：common 组件无业务依赖；business 组件可依赖 api/hooks；页面组件才允许耦合路由
5. **可测性**：纯展示组件导出默认 + 具名；业务逻辑抽 hooks 便于单测

### 5.3 状态管理规范（Zustand）

| Store | 职责 | 持久化 |
|---|---|---|
| authStore | token/用户信息/登录态 | localStorage（token） |
| draftStore | 向导草稿（创意/风格/进度） | localStorage + 服务端 PATCH |
| canvasStore | 画布选中/指令/版本 | 不持久化（服务端为准） |
| uiStore | 全局 loading/通知/会员弹窗 | 不持久化 |

**规则**：服务端状态不进 store（用 react-query 风格自封装 hook 管理缓存/失效）；store 只放跨页共享的客户端状态。

### 5.4 错误边界

- 顶层 `ErrorBoundary`：页面级崩溃 → 兜底页（不白屏）+ 上报
- 路由级 `Suspense` fallback：骨架屏
- 组件内异步错误：错误状态收敛到 hook，UI 显示重试
