## 1. 通用约定

### 1.1 基路径与环境

| 环境 | 基路径 | 说明 |
|---|---|---|
| 开发 | http://localhost:8080/api/v1（Java）/ 5080/api/v1（.NET） | Vite proxy 转发 |
| 容器 | http://backend-java:8080/api/v1 | compose 内网 |
| 生产 | https://api.drawdream.ai/api/v1 | 网关 + 限流 |

### 1.2 统一响应

```json
{ "code": 0, "message": "success", "data": {}, "traceId": "uuid" }
```
（Java/.NET 各实现一个 `ApiResponse<T>` 包装器 + 全局异常处理器，双后端行为一致）

### 1.3 鉴权

- `Authorization: Bearer <JWT>`；JWT 含 `sub`(userId)、`role`(USER/MEMBER/ADMIN)、`exp`
- 游客匿名 token：`type=guest` 前缀，限流 5 req/s；注册后 `/auth/merge` 迁移数据
- **JWT_SECRET 只来自环境变量**（容器 compose 已配占位，生产必须覆盖，长度 ≥32 字节）
- 双后端共用同一密钥与算法（HS256），签名验签一致

### 1.4 幂等

- 所有 POST 写接口读取 `Idempotency-Key` 头（uuid）；服务端 Redis 存 key→响应 24h，重复请求直接返回首次结果
- 生成任务唯一性：同一 creation 同时仅允许 1 个 RUNNING 任务（DB 唯一约束 + 分布式锁）

### 1.5 限流（生产网关 + 应用双层）

| 对象 | 阈值 | 返回 |
|---|---|---|
| 游客 | 5 req/s / IP | 42901 |
| 登录用户 | 30 req/s | 42901 |
| 生成接口 | 并发 1 / 用户 | 42901 |
| 评论/点赞 | 10 req/s | 42901 |

### 1.6 SSE 事件流

`GET /creations/{id}/tasks/{taskId}/events`，事件：
```
event: task_status   data: {"status":"RUNNING","progress":42}
event: step_update   data: {"agent":"编剧","state":"done","output":{"script":"..."}}
event: done          data: {"filmUrl":"...","duration":45}
event: error         data: {"code":"50001","message":"..."}
```
实现：Spring `SseEmitter` / .NET `Response` 流式；横向扩展用 Redis pub/sub 广播。

## 3. 核心接口详细契约（示例 3 个）

### 3.1 启动生成 POST /creations/{id}/generate

**请求头**：`Authorization: Bearer <JWT>`、`Idempotency-Key: <uuid>`

**请求体**：
```json
{
  "styleId": "st_2d_anime",
  "styleStrength": 0.8,
  "aspectRatio": "9:16",
  "durationSec": 45,
  "storyboardOverride": null
}
```

**成功响应 200**：
```json
{ "code": 0, "message": "success",
  "data": { "taskId": "tsk_20260918_001", "status": "QUEUED", "queueNo": 3, "etaSec": 95 } }
```

**错误场景**：42901 额度不足（附 used/quota/upgradeUrl）；40901 已有 RUNNING 任务；40001 参数非法。

**服务端处理顺序（防并发/防刷）**：
1. 校验 JWT + 额度（Redis 计数 + DB 兜底）
2. 幂等键查重 → 命中直接返回
3. 检查并发任务（DB 唯一索引 + Redis 锁）
4. 扣额度（DB 行锁，失败回滚）
5. 写任务 QUEUED → 推 Redis Stream → 返回

### 3.2 画布局部修改 POST /creations/{id}/canvas/edit

**请求体**：
```json
{
  "targetType": "CHARACTER",          // CHARACTER | SCENE | SHOT | MUSIC( P1 )
  "targetRef": { "shotId": "shot_003", "characterId": "char_001" },
  "instruction": "把主角帽子换成红色",
  "confirmation": true                // 前端必须已展示"将重生成受影响镜头"确认
}
```

**响应**：`{ "versionId": "ver_007", "etaSec": 65, "affectedShots": ["shot_003"] }`

**规则**：未传 confirmation=true 返回 40001；修改走**独立编辑任务**（不占月度生成额度，计"编辑额度"P1 引入）。

### 3.3 导出 GET /creations/{id}/export

- 异步任务化：先返回 `{exportTaskId, status:"PROCESSING"}`，前端轮询 `GET /exports/{exportTaskId}`
- 完成返回 `{downloadUrl: "https://oss.../xxx.mp4?X-Amz-Signature=...&Expires=3600"}`
- 签名 URL 由对象存储签发，TTL 1h，防盗链（Referer 白名单）

## 4. 双后端实现要点

| 关注点 | Java（Spring Boot 3.3.5） | .NET（ASP.NET Core 8） |
|---|---|---|
| 响应包装 | `@RestControllerAdvice` 全局异常 → ApiResponse | 中间件 + `IExceptionHandler` |
| 校验 | `jakarta.validation` + 分组校验 | `DataAnnotations` + FluentValidation |
| 鉴权 | Spring Security + JWT Filter | JwtBearer 中间件 |
| 幂等 | Redis + 注解 `@Idempotent` | Redis + ActionFilter |
| 队列 | Spring Data Redis Stream + @EventListener | StackExchange.Redis Stream + BackgroundService |
| SSE | SseEmitter | Response.Body 流式 + 心跳 |
| OpenAPI | springdoc-openapi（Swagger UI /swagger-ui.html） | Swashbuckle（/swagger） |
| 测试 | JUnit + Testcontainers | xUnit + WebApplicationFactory |
| 一致性 | 双后端契约测试 `tests/contract_test.py` 回归保障 | 同左 |

## 5. 服务端安全基线（后端专属）

| 项 | 要求 |
|---|---|
| 输入校验 | 全字段白名单 + 长度/类型/枚举校验；JSON 深度 ≤5 防嵌套炸弹 |
| SQL 注入 | JPA/EF Core 参数化（禁用字符串拼接原生 SQL）；Fluent 校验 |
| 越权 | 资源查询强制 `WHERE owner_id = :userId`（防水平越权）；管理员接口双因子（IP 白名单 + 角色） |
| SSRF | 视频链接解析走代理 + 内网 IP/云元数据段拦截（169.254.169.254） |
| 敏感数据 | 密码 BCrypt cost 10；JWT_SECRET 环境变量；日志脱敏（手机号/身份证） |
| 审核 | 发布内容三级审核：生成时预检 → 发布时审核 → 举报复审 |
| 审计 | 额度流水、审核记录、管理操作全量留痕（credit_transactions / audit_log） |

### 6.3 生成任务 /api/v1/tasks（第 4-5 课）

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | /tasks | 登录 | 提交生成（body: { "draftId": 1 }）→ 201 + PENDING |
| GET | /tasks | 登录 | 我的任务列表（createdAt 倒序） |
| GET | /tasks/{id} | 登录+归属 | 任务详情（越权=404） |
| GET | /tasks/{id}/stream | 登录+归属 | **SSE 进度流**（text/event-stream） |

POST /tasks 语义（教学重点）：
1. 草稿归属校验（404）
2. **幂等**：同草稿已有运行中任务（PENDING/AGENTS/RENDERING/COMPILING）→ 409「正在生成中」（应用层 + PG 部分唯一索引双保险）
3. 建任务（PENDING）→ **扣额度**（悲观锁 + 流水幂等键；余额不足 → 402 INSUFFICIENT_QUOTA）
4. 事务提交后入队（afterCommit，防脏读）

任务状态机（6 态）：PENDING → AGENTS → RENDERING → COMPILING → SUCCESS；任意 → FAILED
- AGENTS 阶段细粒度：gentStage（7 智能体）+ gentProgress（0-100）

SSE 事件格式（GET /tasks/{id}/stream）：
\\\
event:progress
data:{"id":1,"status":"AGENTS","agentStage":"SCREENWRITER","agentProgress":50,"progress":15,"stageMessage":"编剧智能体构思剧情…"}

\\\
- 鉴权：Bearer JWT；先校验归属再订阅（越权订阅 404）
- 终态（SUCCESS/FAILED）推送后服务端 complete() 关闭连接
- 前端连接策略：**SSE 主通道 + 失败自动降级 2s 轮询**（见前端 sse.ts）

### 6.4 错误码补充（第 4 课）

| code | HTTP | 场景 |
|---|---|---|
| 40201 | 402 | 创作额度不足（INSUFFICIENT_QUOTA） |
| 40901 | 409 | 资源冲突（重复提交/非法状态迁移） |

### 6.5 作品（第 6 课：任务 SUCCESS 自动落库）

| 接口 | 方法 | 鉴权 | 说明 |
|---|---|---|---|
| `/works` | GET | ✅ | 我的作品（按创建倒序，含 v1/v2…版本号） |
| `/works/{id}` | GET | ✅ | 作品详情（**越权一律 404**，不泄露存在性） |
| `/works/{id}/regenerate` | POST | ✅ | 重新生成：复用作品草稿再提交任务（201；无该作品=404） |

作品字段：`id / draftId / taskId / title / videoUrl / coverUrl / version / createdAt`

**业务闭环（第 6 课核心）**：`SimulatedTaskWorker` COMPILING → `TaskService.complete(videoUrl)`：
1. 任务 COMPILING → SUCCESS（进度 100，stageMessage=生成完成 🎉）
2. **同一事务**写入作品记录：标题取自草稿、`version = 该草稿已有作品数 + 1`（唯一约束 `(draft_id, version)`）
3. 前端生成成功页「查看作品」→ `/works` 卡片可见

**边界与安全**：
- 作品无独立状态（任务 SUCCESS 才产生作品）→ 作品页无需状态筛选
- `findByIdAndUserId` 归属校验：他人作品读/重新生成均 404
- regenerate 幂等/额度/状态机复用 `POST /tasks`（第 4 课），额度不足 402
- videoUrl 当前为演示外链；生产替换为对象存储（上传→签名 URL→CDN）
