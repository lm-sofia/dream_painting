## 0️⃣ 端口被占用？先杀进程（最常见问题）

### 0.1 释放 8080 端口（Java 后端专用）

```powershell
Get-NetTCPConnection -LocalPort 8080 | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
```

- **何时用**：启动后端报 `Port 8080 was already in use` / BUILD FAILURE 5 秒内退出（典型症状）
- **为什么**：旧 java 进程残留占用端口，Spring Boot 绑定端口失败直接退出
- **判断**：先查再杀更稳妥：`Get-NetTCPConnection -LocalPort 8080`（看 OwningProcess 是不是 java）

### 0.2 释放任意端口（通用模板）

```powershell
Get-NetTCPConnection -LocalPort <端口号> | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
```

- 端口速查：**8080** Java ｜ **5080** .NET ｜ **5173** 前端 Vite ｜ **5432** PostgreSQL ｜ **6379** Redis ｜ **8081** Docker 前端
- **注意**：杀前端 5173 会关掉 dev server；杀 5432/6379 会停数据库（Docker 容器时用 `docker stop` 更合适）

## 1️⃣ 本地开发启动（日常主路径）

> 本地开发只需：**前端 + Java 后端**两个进程。数据库用 H2 内存库（内置），缓存用内存替代，**不需要装 PG/Redis**。

### 1.1 启动 Java 后端（H2 测试环境）

```bash
cd D:\AI-project\backend-java
mvn spring-boot:run "-Dspring-boot.run.profiles=test"
```

- **何时用**：本地开发后端（端口 8080）
- **为什么加 test profile**：切 H2 内存库（免安装）+ 内存缓存（免 Redis）+ 自动灌入种子数据（admin/admin123、alice/user123、8 个风格）
- **验证**：浏览器 `http://localhost:8080/api/v1/health` 返回 `db: UP`

### 1.2 启动前端

```bash
cd D:\AI-project\frontend
npm run dev
```

- **何时用**：本地开发前端（端口 5173）
- **注意**：必须用 Node 22，命令前加 `& "C:\Program Files\nodejs\npm.cmd"`（避免 PATH 里 v20 的坑）
- **为什么不用开 CORS**：Vite proxy 把 `/api` 转发到 8080（同源请求，见 `vite.config.ts`）

### 1.3 启动 .NET 后端（可选，双后端对比时用）

```powershell
cd D:\AI-project\backend-dotnet\AiProject.Api
$env:ASPNETCORE_ENVIRONMENT="Test"
dotnet run --no-build --no-launch-profile --urls http://localhost:5080
```

- **何时用**：验证 .NET 后端或跑双后端契约测试（平时开发跑 Java 即可）

## 2️⃣ Docker 部署（生产形态）

### 2.1 一键启动全家桶（5 容器）

```bash
cd D:\AI-project\docker
docker compose up -d
```

- **启动**：PostgreSQL(5432) + Redis(6379) + Java(8080) + .NET(5080) + 前端 Nginx(8081)
- **为什么**：Docker 容器内后端用默认 profile → 连**真实 PG + Redis**（缓存/队列真正生效）
- **验证**：`docker compose ps` 看 5 个容器都是 Up

### 2.2 只启动数据库（后端本地跑时用）

```bash
cd D:\AI-project\docker
docker compose up -d postgres redis
```

- **何时用**：想本地连真实 PG + Redis 调试缓存/队列（Java 用默认 profile 启动：`mvn spring-boot:run` 不带 profile）

### 2.3 查看/停止容器

```bash
docker compose ps          # 看容器状态
docker compose logs -f java   # 看 Java 容器日志（-f 持续跟随）
docker compose down        # 停止全部（数据卷保留）
docker compose down -v     # 停止并删除数据卷（慎用！会清空数据库）
```

## 4️⃣ 数据库操作

### 4.1 连 PostgreSQL（Docker 版）

```powershell
docker exec -it docker-postgres-1 psql -U app_user -d ai_project
```

- **常用 SQL**：`\dt`（看表）｜ `SELECT * FROM users;`（查用户）｜ `SELECT * FROM styles;`（查风格）
- 密码：`app_password`（见 `docker/docker-compose.yml`）

### 4.2 H2 内存库（本地 test profile）

- 数据在内存里，**重启即清空**——每次启动都是全新种子数据
- 想连 H2 控制台：test profile 下访问 `http://localhost:8080/h2-console`（JDBC URL: `jdbc:h2:mem:testdb`）

## 5️⃣ 常见坑速查

| 症状 | 原因 | 解法 |
|---|---|---|
| 启动 5 秒内 BUILD FAILURE | 8080 被旧进程占用 | 命令 0.1 |
| `ERR_INVALID_ARG_VALUE`（rolldown） | 用了 Node v20（D:\360Install） | 用 Node 22：`& "C:\Program Files\nodejs\npm.cmd"` |
| 登录报 500 且日志有 `JSON parse error` | PowerShell 把 curl 参数里的引号吃掉了 | 用 `curl -d @file.json`（把 JSON 写进文件再传） |
| 种子数据报 `NULL not allowed` | H2 由 JPA 建表**无 DEFAULT**，INSERT 必须显式给所有 NOT NULL 列 | 改 `seed-data.sql` 补列 |
| 新接口 401 但代码明明加了白名单 | 8080 上跑的是旧代码进程 | 命令 0.1 后重启 |
| antd chunk > 600KB 警告 | antd 是共享依赖只能整包（gzip 215KB 正常） | 阈值已调到 700，无需处理 |
