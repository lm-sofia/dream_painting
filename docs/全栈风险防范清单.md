## 8. 监控与告警体系（必须上线前接通）

```text
基础设施层：CPU/内存/磁盘/网络（Prometheus + Grafana）
应用层：接口 P99 延迟、错误率、5xx、慢 SQL（Spring Actuator / .NET HealthChecks）
业务层：生成失败率、任务队列水位、审核积压数、额度异常、成本环比
安全层：登录失败率、异常 IP、审核驳回率、越权尝试
告警分级：P0（服务不可用/数据丢失）→ 电话 + 群；P1（错误率>5%）→ 群 + 值班；P2（容量预警）→ 群
```

**告警原则**：先有日志和指标，再谈告警；每个告警必须有明确响应动作（避免告警疲劳）。

## 9. 上线门禁（Go/No-Go 清单）

- [ ] 契约测试（双后端）+ E2E + 安全用例全部通过
- [ ] 密钥扫描 + 依赖漏洞扫描 + 镜像扫描 0 高危
- [ ] 备份策略生效 + 恢复演练完成 1 次
- [ ] 监控/告警接通并有响应值班
- [ ] 成本模型 + 额度上限验证（单用户最大消耗 ≤ 月费 3 倍）
- [ ] 内容审核链路（预检→发布→举报）实测通过
- [ ] 回滚演练：镜像可一键回退上一版本
- [ ] 隐私政策/用户协议/版权声明上线

## 10. 风险演进机制

1. **每版本评审**：新功能上线前过一遍本清单相关项
2. **事故复盘**：任何 P0/P1 事故 48h 内出复盘，沉淀进清单"响应"列
3. **清单版本化**：本文随项目迭代更新（changelog 在文末追加）
