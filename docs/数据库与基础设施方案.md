## 1. 数据库设计（PostgreSQL 16）

### 1.1 核心表 DDL 要点（增量扩展现有 database/init/01_create_schema.sql）

```sql
-- 用户表（现有 + 游戏化字段）
ALTER TABLE users ADD COLUMN level INT DEFAULT 1;
ALTER TABLE users ADD COLUMN continuous_days INT DEFAULT 0;
ALTER TABLE users ADD COLUMN invite_code VARCHAR(12) UNIQUE;
ALTER TABLE users ADD COLUMN invited_by BIGINT REFERENCES users(id);
CREATE INDEX idx_users_invite ON users(invite_code);

-- 创意主表
CREATE TABLE creations (
  id BIGSERIAL PRIMARY KEY,
  user_id BIGINT NOT NULL REFERENCES users(id),
  title VARCHAR(100) NOT NULL,
  content TEXT NOT NULL,
  style_id VARCHAR(32),
  style_strength NUMERIC(3,2) DEFAULT 0.8,
  aspect_ratio VARCHAR(10) DEFAULT '9:16',
  template_id BIGINT REFERENCES templates(id),
  status VARCHAR(16) NOT NULL DEFAULT 'DRAFT',  -- DRAFT/GENERATING/SUCCESS/FAILED
  current_version_id BIGINT,
  created_at TIMESTAMPTZ DEFAULT now(),
  updated_at TIMESTAMPTZ DEFAULT now()
);
CREATE INDEX idx_creations_user_status ON creations(user_id, status, created_at DESC);
CREATE INDEX idx_creations_template ON creations(template_id);

-- 生成任务（含智能体步骤状态，jsonb）
CREATE TABLE tasks (
  id BIGSERIAL PRIMARY KEY,
  creation_id BIGINT NOT NULL REFERENCES creations(id),
  status VARCHAR(16) NOT NULL,           -- QUEUED/RUNNING/SUCCESS/FAILED/CANCELLED
  step_states JSONB NOT NULL DEFAULT '{}',  -- {艺术总监:{state,output},...}
  progress INT DEFAULT 0,
  error_code VARCHAR(16),
  retry_count INT DEFAULT 0,
  model_used VARCHAR(64),
  created_at TIMESTAMPTZ DEFAULT now(),
  finished_at TIMESTAMPTZ,
  idempotency_key VARCHAR(64) UNIQUE,    -- 幂等唯一约束
  UNIQUE (creation_id, status) WHERE status = 'RUNNING'  -- 部分唯一索引：同创作仅1个运行中任务
);
CREATE INDEX idx_tasks_status_created ON tasks(status, created_at);

-- 资产（分离式渲染三层落盘的关键）
CREATE TABLE assets (
  id BIGSERIAL PRIMARY KEY,
  task_id BIGINT NOT NULL REFERENCES tasks(id),
  type VARCHAR(16) NOT NULL,  -- CHARACTER/SCENE/MUSIC/STORYBOARD/FRAME/SHOT_VIDEO
  object_key VARCHAR(255) NOT NULL,   -- 对象存储 key（分层前缀：u{uid}/c{cid}/shot/...）
  thumbnail_key VARCHAR(255),
  meta JSONB,                          -- 角色锚点特征/镜头时长/分辨率
  created_at TIMESTAMPTZ DEFAULT now()
);
CREATE INDEX idx_assets_task_type ON assets(task_id, type);

-- 版本（画布回滚）
CREATE TABLE versions (
  id BIGSERIAL PRIMARY KEY,
  creation_id BIGINT NOT NULL REFERENCES creations(id),
  parent_version_id BIGINT REFERENCES versions(id),
  change_log VARCHAR(200),
  film_object_key VARCHAR(255),
  duration INT,
  created_at TIMESTAMPTZ DEFAULT now()
);
CREATE INDEX idx_versions_creation ON versions(creation_id, created_at DESC);

-- 社区
CREATE TABLE posts (
  id BIGSERIAL PRIMARY KEY,
  creation_id BIGINT NOT NULL,
  user_id BIGINT NOT NULL,
  title VARCHAR(30) NOT NULL,
  tags VARCHAR(20)[] DEFAULT '{}',
  cover_key VARCHAR(255),
  video_key VARCHAR(255),
  like_count INT DEFAULT 0, comment_count INT DEFAULT 0, remix_count INT DEFAULT 0,
  status VARCHAR(16) DEFAULT 'PENDING',  -- PENDING/APPROVED/REJECTED
  challenge_id BIGINT,
  created_at TIMESTAMPTZ DEFAULT now()
);
CREATE INDEX idx_posts_status_created ON posts(status, created_at DESC);
CREATE INDEX idx_posts_user ON posts(user_id, created_at DESC);
CREATE INDEX idx_posts_challenge ON posts(challenge_id) WHERE challenge_id IS NOT NULL;

-- 点赞（唯一约束防重 = 幂等）
CREATE TABLE likes (
  post_id BIGINT NOT NULL, user_id BIGINT NOT NULL, created_at TIMESTAMPTZ DEFAULT now(),
  PRIMARY KEY (post_id, user_id)
);

-- 关注（唯一约束防重）
CREATE TABLE follows (
  follower_id BIGINT NOT NULL, followee_id BIGINT NOT NULL, created_at TIMESTAMPTZ DEFAULT now(),
  PRIMARY KEY (follower_id, followee_id)
);

-- 额度流水（审计核心）
CREATE TABLE credit_transactions (
  id BIGSERIAL PRIMARY KEY,
  user_id BIGINT NOT NULL,
  delta INT NOT NULL,               -- +10 赠送 / -1 生成 / +1 返还
  reason VARCHAR(32) NOT NULL,      -- GENERATE/REFUND/INVITE/DAILY_BONUS
  ref_id BIGINT,                    -- 关联任务/邀请
  created_at TIMESTAMPTZ DEFAULT now()
);
CREATE INDEX idx_ct_user_time ON credit_transactions(user_id, created_at DESC);

-- 审核日志
CREATE TABLE audit_log (
  id BIGSERIAL PRIMARY KEY,
  actor_id BIGINT, action VARCHAR(32), target_type VARCHAR(32), target_id BIGINT,
  detail JSONB, created_at TIMESTAMPTZ DEFAULT now()
);
CREATE INDEX idx_audit_target ON audit_log(target_type, target_id);
```

### 1.2 关键设计决策（防坑）

| 决策 | 理由 |
|---|---|
| 部分唯一索引 `UNIQUE (creation_id,status) WHERE status='RUNNING'` | 数据库层强制"同一创作同时仅 1 个运行任务"，防并发绕过应用锁 |
| `idempotency_key UNIQUE` | 幂等下沉到 DB，应用层 Redis 只是缓存 |
| 游标分页（WHERE created_at < :cursor ORDER BY created_at DESC LIMIT 20） | 避免 OFFSET 深分页性能恶化 |
| 计数列（like_count 等） | 列表页不实时 COUNT，读写分离后 5min 异步校准 |
| 审核状态索引 | PENDING 队列是审核页高频查询 |
| JSONB 存智能体状态/模板结构 | 结构灵活（7 智能体字段会演进），配合 GIN 索引可查询 |

## 2. 数据库优化

### 2.1 索引与查询

- 所有 FK 列建索引（PostgreSQL 不自建）；组合索引遵循"等值在前、范围在后"
- 高频查询预热：`explain analyze` 全量走查一遍关键 SQL，杜绝 Seq Scan 扫大表
- 大字段（content/step_states）不进列表查询（SELECT 只取需要的列）

### 2.2 连接池与容量

| 项 | 配置 |
|---|---|
| 连接池（HikariCP/Npgsql） | max 20 / 连接，最小 5；`connectionTimeout 3s`（快速失败不堆积） |
| 空闲连接 | 10min 回收；`leak-detection-threshold 10s` 抓连接泄漏 |
| 慢查询 | `log_min_duration_statement = 500ms` + pgbadger 周报 |
| 容量预估 | 用户 10 万 / 作品 50 万 / 点赞 500 万：单机 32GB 内存可扛，峰值后再加只读副本 |

### 2.3 读写分离（放量后）

- 主库写 + 2 只读副本（PgPool-II 或云 RDS 自动）；读路由：列表/详情/广场走只读
- 复制延迟敏感场景（发布后立即看自己作品）强制主库读（`session_replication_role` 或短 TTL 缓存直通）

## 3. 数据库安全

| 项 | 方案 |
|---|---|
| 最小权限 | 应用账号仅 DML + 指定表权限；DDL 用迁移账号（Flyway/Ef Migrations），生产分离 |
| 敏感字段 | 手机号/邮箱加密存储（AES-256-GCM，应用层密钥由 KMS/环境变量注入）；昵称等展示字段脱敏中间件 |
| 连接加密 | SSL/TLS（云 RDS 默认；自建 pgbouncer 终止） |
| 审计 | audit_log 记录：登录、额度变动、审核、管理操作（法律合规 + 追溯） |
| 备份加密 | pg_dump 备份落盘加密（gpg）；对象存储生命周期 30 天 |
| 防误删 | 生产库无 DROP/TRUNCATE 权限；危险操作需双人审批（变更流程） |
| 数据导出 | 导出脱敏 + 审批留痕（PIPL 合规） |

## 4. 缓存策略（Redis 7）

### 4.1 分层

| 层 | 内容 | TTL | 淘汰 |
|---|---|---|---|
| L1 本地 | 高频只读（风格列表/公告） | 5min | LRU |
| L2 Redis | 热门作品流（前 200 条）、模板列表、用户额度计数、验证码、幂等键 | 见下 | LRU |
| L3 DB | 全量数据 | — | — |

### 4.2 关键缓存设计

| 数据 | key 模式 | TTL | 失效策略 |
|---|---|---|---|
| 热门广场 | `feed:hot:{page}` | 60s | 写操作 + 定时重建（5min） |
| 作品详情 | `post:{id}` | 10min | 删除型失效（点赞/评论更新时删 key） |
| 额度计数 | `credits:{userId}` | 当天 | 扣减即更新（Lua 原子操作）+ DB 兜底对账 |
| 验证码 | `sms:{phone}` | 5min | 防爆破：60s 重发间隔 + 5 次错误锁定 |
| 幂等键 | `idem:{key}` | 24h | 命中直接返回 |
| 任务进度 | `task:{id}` | 30min | worker 写入，SSE 订阅 |
| 模板署名计数 | `tpl:usage:{id}` | 10min | 异步落库 |

### 4.3 防缓存击穿/穿透/雪崩

- **穿透**：空值也缓存（TTL 60s）+ 布隆过滤器（热门 id 集合）
- **击穿**：热点 key 用互斥锁重建（SETNX）+ 逻辑过期（value 内嵌过期时间，后台异步刷新）
- **雪崩**：TTL 加随机 ±20%；热点数据永不过期 + 定时刷新

## 5. 存储方案（视频/图片/音频）

### 5.1 对象存储分层（MinIO 自建 / 云 OSS 二选一，建议云 OSS 起步省运维）

```text
u{userId}/c{creationId}/
  shots/shot_001.mp4          # 镜头级视频（分离式渲染）
  film/v1.mp4                 # 版本成片
  assets/char_001.png         # 角色种子资产
  assets/scene_001.png        # 场景种子资产
cover/{postId}.webp           # 封面（CDN 加速）
```

### 5.2 上传/下载链路

```
前端 → POST /uploads/presign（服务端签发 5min 有效期）→ 直传 OSS → 服务端回调验证（大小/类型/内容审核）→ 记录 asset
播放/下载 → 签名 URL（TTL 1h + Referer 防盗链）
```

### 5.3 视频处理（FFmpeg 服务）

| 任务 | 处理 | 产出 |
|---|---|---|
| 转码 | H.264 + AAC（全端兼容） | 1080p/720p 双码率 |
| 封面 | 首帧抽图 + WebP | cover.webp |
| 水印 | 会员判定：免费导出叠加"绘梦工坊"角标 | watermarked.mp4 |
| 竖屏优化 | 9:16 主场景原生生成，不做裁切（内容为王） | — |

### 5.4 CDN 与成本

- 视频/封面全量 CDN（预热热门作品）；回源走内网 OSS
- 成本控制：低清预生成（480p 预览）→ 会员才出 1080p；历史版本保留策略（≤3 版原始文件，旧版转 480p 存档）
- 生命周期：草稿/失败任务的临时文件 24h 清理（对象存储生命周期规则）

## 6. 任务队列（Redis Stream）与 Worker 架构

```text
[API 层] 写任务 QUEUED ──▶ Redis Stream:task:pipeline
                                │ worker 池（Java/.NET 各一组，按能力消费）
                                ▼
[Worker 链] 7 智能体阶段链：艺术总监→编剧→角色→场景→动画→剪辑→音效
   每阶段独立消费组（xreadgroup），产物写 OSS + assets 表
   失败 → retry_count+1 → 重投队列（≤3）→ 超限 FAILED + 告警
   Worker 崩溃 → 消息未 ACK → 回到 PEL 可重领（At-Least-Once + 幂等）
```

**关键点**：阶段链保证"分离式渲染"（镜头独立生成、轨道分层落盘），是局部修改（附录 A）的技术前提。

## 7. 备份与容灾

| 项 | 策略 |
|---|---|
| 数据库 | 每日全量（pg_dump，保留 14 天）+ WAL 归档（PITR 可恢复至秒级，保留 30 天） |
| Redis | 开启 AOF everysec；作为缓存可容忍重建，不做异地 |
| 对象存储 | 版本控制 + 跨区域复制（视频成本高，恢复优先级最高） |
| 演练 | 每月一次恢复演练（RTO ≤ 4h，RPO ≤ 5min）；演练结果留档 |
